## 2024-05-10 - Replace FNV-1a with maphash
**Learning:** `vortex-cache` uses a custom FNV-1a hash implementation for routing keys to shards. Go's built-in `hash/maphash` is significantly faster (especially on architectures with AES-NI instructions) because it's implemented in assembly and uses a fast hash algorithm (based on AES/Wyhash).
**Action:** Replace custom FNV-1a hashing with `hash/maphash` to speed up key routing across all operations (`GET`, `SET`, `DEL`, etc.).
## 2024-05-24 - Remove unused Entry timestamps to eliminate data race and reduce memory
**Learning:** The `Entry` struct in `vortex-cache` stored `CreatedAt` and `AccessedAt` timestamps. `AccessedAt` was updated during `Get` operations under an `RLock`, leading to a data race because multiple goroutines could update it simultaneously without a write lock. Furthermore, since `vortex-cache` handles lazy expiration internally and its default LRU eviction policy works using a separate doubly-linked list (`lruNode` in `lru.go`), these timestamps weren't actually used for eviction or correctness. They merely caused data races and wasted 16 bytes of memory per key.
**Action:** Removed unused `CreatedAt` and `AccessedAt` fields from `Entry` struct and eliminated the write to `AccessedAt` in the `Get` method, safely fixing the race condition and optimizing memory utilization (shaving 16 bytes off the `Entry` struct size).
